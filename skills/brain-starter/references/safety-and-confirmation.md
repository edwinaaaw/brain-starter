# Gmail and Calendar safety

Use available tools only when they materially reduce the current startup resistance.

## Read scope

When the user directly names a person, topic, event, or date, read within that scope. For a vague “what should I do?” request, ask permission before reading, then search in this order:

1. user-named person or topic;
2. mail related to today's Calendar events;
3. the last 72 hours with a clear action request;
4. starred or user-marked mail.

Return at most three candidates initially. Do not scan the whole mailbox speculatively.

## Action classes

- **May prepare without a second confirmation:** draft text, extract action items, summarize relevant scheduling facts, propose a personal focus block.
- **Confirm immediately before execution:** send mail, reply-all, forward, create an event inviting others, or modify an existing event.
- **Unsupported in v1:** delete mail or events.

Do not place tokens, account identifiers, message bodies, attachments, or unrelated private content in session logs. If Gmail or Calendar is unavailable, say so once and continue from user-provided context; do not block the start.
